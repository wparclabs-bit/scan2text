## Root Cause Analysis

The spec correctly bundles `pdfium.dll` into `a.binaries` with subdir `'pypdfium2_raw'`. PyInstaller one-file mode extracts binaries to `_MEIPASS/` preserving subdirectory structure, so the DLL should land at `_MEIPASS/pypdfium2_raw/pdfium.dll`.

However, `pypdfium2_raw.bindings._get_library` resolves the path using `pathlib.Path(__file__).parent`. In PyInstaller one-file mode, `__file__` for modules extracted from the PYZ archive points to the extracted temp location. **If the DLL extraction lags behind the import** (lazy extraction), or if the subdirectory structure is not preserved for this particular binary tuple, the resolved path does not exist and `_get_library` raises `ImportError("Could not find library 'pdfium' ...")`, leaving `pdfium` undefined → `name 'pdfium' is not defined`.

The error is a **NameError** (not ImportError), confirming that `pypdfium2_raw` imports successfully but the `_libs['pdfium']` assignment fails silently or the exception is caught upstream, leaving `pdfium` unbound.

## Proposed Fix

**Add a PyInstaller runtime hook** (`packaging/runtime_hooks/patch_pypdfium2.py`) that patches `pypdfium2_raw.bindings._get_library` to resolve the DLL against `sys._MEIPASS` instead of `__file__`:

```python
# packaging/runtime_hooks/patch_pypdfium2.py
import os
import sys
import pathlib
import pypdfium2_raw.bindings

_original_get_library = pypdfium2_raw.bindings._get_library

def _patched_get_library(name, dllclass, libpaths, search_sys):
    if getattr(sys, 'frozen', False) and hasattr(sys, '_MEIPASS'):
        # In frozen mode, force the path to _MEIPASS/pypdfium2_raw/
        frozen_path = pathlib.Path(sys._MEIPASS, 'pypdfium2_raw', f'{name}.dll')
        if frozen_path.exists():
            return dllclass(str(frozen_path))
    return _original_get_library(name, dllclass, libpaths, search_sys)

pypdfium2_raw.bindings._get_library = _patched_get_library
```

Then update the spec to reference it:

**File:** `packaging/scan2text-backend.spec`
**Line 18** (after `excludes = [...]` block, before collection blocks):
```python
runtime_hooks=['../packaging/runtime_hooks/patch_pypdfium2.py'],
```

**Alternative (simpler) fix:** Set `PATH` environment variable in the runtime hook to include `_MEIPASS/pypdfium2_raw/`, so the system DLL search path finds `pdfium.dll` before the `__file__`-relative resolution is attempted. But this is less reliable because the loader explicitly constructs a path and checks `.exists()` before calling `CDLL`.

**Chosen approach:** Patch `_get_library` directly (first option). It is deterministic, does not depend on DLL search path ordering, and works for both onefile andonedir modes.
